## 1. 目的

obsidian-kanbanを参考に、個人利用に特化したObsidianバックエンドの看板プラグインを新規開発する。
Markdownファイルを唯一のデータソースとし、ファイル形式はobsidian-kanban互換を維持する。
obsidian-kanbanのソースコードは流用せず、参照資料として扱う。

## 2. スコープ

### やること(コア機能)

- ボード表示(固定5レーン: TODO / DOING / TODAY / DONE / PENDING)
- ボード内のカード移動(レーン内の並べ替え+レーン間の移動、ドラッグ&ドロップ)
- カードの作成・タイトル編集・削除
- 完了レーンのカードの年月別一括アーカイブ
- カードメタデータ(登録日・完了日)の自動管理
- レーンヘッダーへのタイトルとカード数の表示

### やらないこと

| 機能 | 理由 | 将来の追加容易性 |
|---|---|---|
| マルチウィンドウ(ポップアウト)対応 | 使用しない | 困難(横断的改修) |
| ボード間のカード移動 | 不要 | 困難(マウント構造に影響) |
| 外部ドロップ/ペーストでのカード作成 | ユースケースなし | 容易(入口の追加のみ) |
| レーンの折りたたみ | 使用しない | 中程度 |
| レーンのCRUD UI・左右移動 | レーン固定のため不要 | 容易(状態操作関数は用意済み) |
| テーブル/リスト表示 | ボード表示のみで十分 | 中程度 |
| モバイル(タッチ)対応 | デスクトップ専用 | 中程度(ライブラリ依存) |
| カード内の日付・タグ等の解釈 | 表示はタイトルのみ | 中程度(パーサー差し替えで対応可) |
| WIP制限・レーン属性 | 不要 | 容易 |
| 削除・移動のUndo | 個人用には過剰 | 中程度。回復手段は5.5参照 |

## 4. データ仕様(Markdownフォーマット)

### 4.1 基本構造

obsidian-kanban互換。新規ボード作成時に以下のテンプレートを生成する。

```markdown
---
kanban-plugin: board
---

## TODO

## DOING

## TODAY

## DONE

**Complete**

## PENDING
```

- frontmatterの `kanban-plugin` キーが看板ファイルの識別子
- `## 見出し` = レーン。レーンはコードにハードコードせず、ファイルにある見出しを読む(レーン構成の変更はMarkdownの手編集で可能)
- `- [ ] テキスト` = カード。`- [x]` は完了カード
- 完了レーンの識別は見出し名ではなく、見出し直下の `**Complete**` 段落で行う(obsidian-kanban互換マーカー、
  本家実装の判定方法とも一致)。レーン名を手編集で変えても完了同期(5.3)は壊れない。
  テンプレートではDONEレーンにこのマーカーを付与する

### 4.2 カードメタデータ

Tasksプラグイン形式(絵文字)を採用する。

```markdown
- [ ] 資料を作成する 2026-06-01
- [x] 資料を作成する 2026-06-01 2026-06-11
```

| 記号 | 意味 | 付与タイミング |
|---|---|---|
| ` YYYY-MM-DD` | 登録日 | UIからのカード作成時に自動付与 |
| ` YYYY-MM-DD` | 完了日 | 完了レーンへの移動時に自動付与 |

採用理由: obsidian-tasksプラグインの標準書式であり、Dataviewもタスクフィールドとして解釈するため、
プラグインに機能を足さなくても将来Dataviewクエリでの集計(例: 今週完了したカードの一覧)が可能になる。

メタデータの判定・操作ルール:

1. 対象は1行目のみ — メタデータの付与・分離はカードの1行目(チェックボックス行)の末尾のみを対象とする。
   複数行カード(4.4)の2行目以降は対象外(obsidian-tasks / Dataviewも1行目しか解釈しないため)
2. 判定ルール — 1行目の行末から連続する「` ` または ` ` + 半角スペース + `YYYY-MM-DD`」のトークン列のみを
   メタデータとみなす。末尾連続列より前(本文中)に現れる同じ絵文字は本文として扱い、一切触らない
   (例: `- [ ] マークの仕様を調べる` の ` ` は本文)
3. 同種トークンが複数ある場合 — 末尾トークン列内に同種トークンが複数あるとき(手書き等)、値としては
   最後のものを採用する。除去時(完了レーンから出すときの ` ` 除去)は列内の同種トークンをすべて除去する
4. タイトル編集時も同一ルール — 編集内容の保存時にも上記の分離ルールを適用する。ユーザーが末尾に
   ` YYYY-MM-DD` 等を手入力した場合はメタデータに昇格し、既存値を上書きする
   (本文扱いにすると自動付与トークンと並んで次回パースで区別不能になるため。判定ルールは常に1つ)
5. 「今日」の定義 — 日付は端末のローカル日付を使用する

### 4.3 アーカイブ

obsidian-kanban互換。ファイル末尾の `***` 区切り以下に退避する。完了レーンのカードを年月別に
**一括**で退避する操作として提供する(カード1枚ずつのアーカイブは行わない。操作仕様は5.6)。

```markdown
***

## Archive

### 2026-06

- [x] 完了済みのカード ➕ 2026-06-01 ✅ 2026-06-20

### 2026-05

- [x] 先月完了したカード ➕ 2026-05-01 ✅ 2026-05-10
```

- 年月別グルーピング: `## Archive` の下に `### YYYY-MM` の小見出しを設け、その年月に属する
  完了カードを束ねる。小見出しは新しい年月が上に来る降順で並べる
- 年月の判定基準: 完了日 `✅` の年月を採用する。`✅` を持たないカードは登録日 `➕`、それも無ければ
  アーカイブ実行日(端末のローカル日付、4.2の「今日」と同じ)にフォールバックする
- アーカイブ操作の意味論: カードの状態を変えずそのまま退避する(`✅` の付与も `[x]` 化もしない。
  完了日の付与は完了レーンへの移動時に済んでいる(5.3))。結果としてアーカイブ内に未完了カード
  (`- [ ]`)が混在することを許容する(raw保存原則との一貫性を優先)
- 既存アーカイブの非破壊: 本機能の導入前から `## Archive` 直下にフラットに溜まっているカードや、
  手編集・本家が書き込んだアーカイブ内容は再整理しない。そのままの位置に温存し、年月別の整理は
  本機能で新たに退避するカードにのみ適用する(`### YYYY-MM` 小見出しと既存のフラットなカードが
  同一アーカイブ内に混在することを許容する)

### 4.4 raw保存原則(ラウンドトリップの無損失性)

パーサーの設計原則: 理解できるものだけ構造化し、理解できないものは位置ごと保存する。

- カード本文は不透明な生文字列(`titleRaw`)として保持する。解釈するのは1行目末尾のメタデータ
  (` `/` `、4.2の判定ルール)の分離のみ
- 表示タイトル = 生文字列からメタデータ部分を除いたもの
- レーンについて構造として解釈する属性は、見出し直下の `**Complete**` 段落(完了レーン属性)のみ。
  それ以外のレーン直下の段落は「想定外のブロック」(下記4)として温存する
- 本家やほかのプラグインが書き込んだ記法(`@{日付}`、タグ、`^ブロックID`、`[key:: value]` 等)は
  解釈せず生文字列の一部として無傷に往復させる

必須エッジケース対処:

1. 複数行カード — カード直下にインデントされた続きの行・サブ項目は、カードの生文字列に含めて
   一体で保持する(移動・編集時に欠落させない)
2. frontmatterと設定ブロック — 冒頭のYAMLと末尾の `%% kanban:settings %%` ブロックは解釈せず
   そのまま書き戻す
3. アーカイブセクション — `***` 区切り以下を通常レーンと区別して保持する
4. 想定外のブロック — 見出しの間の裸の段落など、リストでも見出しでもないものはその位置に温存する
5. 書式の非正規化 — チェックボックスの文字(`[X]`、`[/]` 等のカスタムステータス)やリスト記号は
   書き換えない。読んだままを書く

## 5. 機能仕様

### 5.1 ボードの作成と表示

- 新規ボード作成はコマンドパレットのコマンド1本で行う(テンプレート(4.1)を生成して看板ビューで開く)。
  リボンアイコン等の追加の入口は作らない
- レーンを横並びに表示。レーンヘッダーにタイトルとカード数(導出値、永続化しない)を表示
- カードは表示タイトルのみ表示(メタデータ・チェックボックスは表示しない)

### 5.2 カード操作

| 操作 | 仕様 |
|---|---|
| 作成 | レーン内の追加UIから。` 今日` を自動付与 |
| タイトル編集 | インライン編集。保存時に4.2のメタデータ分離ルールを適用する |
| 移動 | D&D(レーン内並べ替え・レーン間移動)。状態操作は `moveItem(from, to)` に集約 |
| 削除 | カードメニューから。確認ダイアログ必須 |

カード単位のアーカイブは提供しない。アーカイブは完了レーンのカードを年月別に一括退避する操作として
ボード/レーン側から行う(5.6)。

### 5.3 完了の扱い(完了レーンとの同期)

完了状態はレーン位置から導出する。チェックボックスUIは設けず、操作はD&Dに一本化する。
「完了レーン」とは `**Complete**` マーカー付きのレーンを指す(4.1)。

- 完了レーンへ移動: ` 今日` を付与し、`- [x]` にする
- 完了レーンから出す: ` ` を除去し、`- [ ]` に戻す(再度完了レーンに入れば新しい完了日が付く)
- メタデータとチェック状態に触るのは完了レーン境界の出入りのみ。非完了レーン同士の移動や
  レーン内並べ替えでは、`[x]`/` ` の状態がどうであれ一切触らない
- 手書きカードの許容: ` ` のないカードは欠損のまま許容する(勝手に書き換えない)。
  完了レーン以外にある `[x]` カードも読み込み時には触らない(ファイルが正)

### 5.4 レーン

- CRUD UIなし。テンプレート生成のみ
- レーン構成の変更はMarkdownの手編集で行う(パーサーは見出しを汎用に読むため対応不要)

### 5.5 削除の安全性と回復手段

- 不可逆な削除操作には必ず確認ダイアログを挟む
- アーカイブ(5.6)は完了カードの整理手段である。退避先は同一ファイル内のため、
  閲覧・復元はmarkdownモードでの手編集で足りる。専用UIは作らない)
- Undoは実装しない(2章)。誤操作(削除)の回復手段は次に委ねる:
  ObsidianコアのFile Recovery(スナップショット)

### 5.6 アーカイブ(完了カードの年月別一括退避)

完了レーンのカードを年月別に一括で `## Archive` へ退避する(データ仕様は4.3)。

- 入口は2つ: コマンドパレットのコマンドと、完了レーンのヘッダーメニュー
- 対象は `**Complete**` マーカー付きのレーン(4.1)。完了レーンが複数ある場合はそのすべてを対象とし、
  同一のアーカイブセクションへ集約する
- 退避時、各カードを完了日 `✅` の年月(無ければ `➕` →実行日)で `### YYYY-MM` 小見出しに振り分ける(4.3)
- カードの状態は変えない(`✅` の付与も `[x]` 化もしない、4.3)
- 退避後、対象の完了レーンは空になる。実行前に件数を示す確認ダイアログを挟む(5.5)
- 対象カードが無い場合は何もしない(no-op)

## 6. アーキテクチャ方針

obsidian-kanbanから設計パターンのみ引き継ぐ。

1. ファイルごとの状態管理(StateManagerパターン) — パース済みボードを唯一の状態として保持し、
   状態変更時に「再描画」と「Markdown書き出し→保存」を同時に駆動する。Svelte 5のrunes
   (`$state`)で実装し、自前pub/subは持たない
2. 状態操作の一本化 — `addCard` / `updateCardTitle` / `moveItem` / `archiveCompletedCards` /
   `deleteCard` 等の操作関数に集約する。UI(D&Dライブラリ含む)はこれらを呼ぶだけの存在とし、
   ライブラリの差し替え・機能の後付け(外部ドロップ等)を接続コードの追加だけで可能にする
3. D&Dは接続層 — svelte-dnd-actionのイベントを `moveItem` 呼び出しに変換する薄い層に閉じ込める。
   行き詰まった場合の乗り換え(SortableJS等)を想定した分離を保つ
4. 描画の安定性 — カードに安定したkeyを与え、ドロップ後の再描画でちらつきが出ないことを
   受け入れ条件とする
5. 自己保存エコーのガード — 自プラグインの保存が発火させる `vault.modify` イベントを外部編集と
   誤認しないこと。保存直前に書き込んだ内容を記録し、modifyイベント受信時に記録と一致する場合は
   無視する。8章3項(外部編集の全再パース方式)の前提条件であり、これを欠くと
   保存→再パース→再描画のループとドロップ直後のちらつきが発生する

## 7. 互換性方針

- 本プラグインで編集したファイルはobsidian-kanbanでそのまま開けること(フォーマット互換)
- 本プラグインが解釈しない記法を含むファイルを開いて編集しても、その記法を破壊しないこと
  (raw保存原則)
- メタデータはobsidian-tasks / Dataviewから解釈可能であること
- 注意: frontmatterキーを本家と同じ `kanban-plugin` にするため、obsidian-kanbanと本プラグインを
  同時に有効化するとビューの取り合いが起こる。同時利用はしない前提とする

## 8. 確定済みの判断(旧・未決事項)

v0.1で未決としていた4点は、レビューを経て以下の通り確定した。

1. ビュー切替 — 明示的切替(コマンド+ファイルメニュー)で開始する。本家の
   `WorkspaceLeaf.setViewState` モンキーパッチによる自動切替は、Obsidianのアップデートで
   壊れうる非公開API依存のため初期実装では採用しない。明示切替の不便を体感してから導入を再判断する
2. カード本文のMarkdownレンダリング — 二段階とする。第一段階はプレーンテキスト表示。
   Obsidianの `MarkdownRenderer` APIによるリッチ表示(内部リンク等)は第二段階
3. 外部編集(別タブ・同期)の反映 — 全再パース+全再描画で開始する。自己保存エコーガード
   (6章5項)を前提条件とし、ちらつきが問題になった場合のみ差分適用を検討する
4. frontmatterキー — `kanban-plugin` を維持する。本家でいつでも開ける互換性の実利を優先し、
   同時有効化の衝突(7章)は運用で回避する

## 9. テスト方針

本仕様で最もリスクが高いのはパーサーであり、同時に最も機械的に守れる部分でもあるため、
パーサーのテストを受け入れ条件とする。

1. ラウンドトリップテスト(必須) — 「パース→シリアライズ」の往復でファイル内容が一致することを
   ゴールデンファイルで検証する。フィクスチャには最低限以下を含める:
   - 4.4の必須エッジケース5項目(複数行カード、frontmatter/設定ブロック、アーカイブ、
     想定外ブロック、カスタムチェックボックス文字)
   - 本家obsidian-kanbanが生成したファイル(日付 `@{}`・タグ・ブロックID入り)
2. メタデータ分離の単体テスト — 4.2の判定ルールを網羅する:
   本文中の絵文字、複数 ` `、` ` 欠損、編集時の昇格・上書き
3. 完了同期のテスト — 完了レーン境界の出入りでの ` `/`[x]` の付与・除去、
   非完了レーン間移動で何も変わらないこと
4. 一括アーカイブの単体テスト(5.6/4.3) — 完了日 `✅` の年月への振り分け、`✅` 欠損時の `➕` →実行日
   へのフォールバック、`### YYYY-MM` 小見出しの新設・既存月への追記・降順、導入前から溜まっている
   フラットなアーカイブを壊さないこと、複数の完了レーンの集約、対象なし時の no-op を網羅する
5. 手動の受け入れ確認 — ドロップ後の再描画でちらつきが出ないこと(6章4項)、
   本家プラグインで開いて表示・編集できること(7章)
